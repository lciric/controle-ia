## 1. Corrections (fichiers neufs, R12 : les v1 à v8 restent telles quelles)
Fichiers : `scripts/amorce_instance_t06_v7.sh`, `scripts/lancer_t06_v9.sh`, `src/controle_ia/t06/session_v8.py` (au-dessus de `session_v7.py` et `session_v2.py`, qui ne changent pas).

1. **R-1689 / R-1690, concurrence C08 contre la destruction** (amorce v7, deux gestes) : (a) avant de lancer la minuterie, si l'heure de dépense épuisée est déjà passée et que le marqueur manque, l'amorce le pose (« dépense déjà épuisée au démarrage ») : la minuterie ne prend plus la branche C08 ; (b) dans la minuterie, après la consignation de C08, `PUT stopped` n'est plus envoyé si `t06-detruire` est apparu. Essais qui reproduisent la concurrence (`tests/test_t06_v7_amorce_minuterie.py`) : v6 envoie `PUT stopped` (défaut), v7 n'envoie que `DELETE`. Effet de bord déclaré : un run interrompu redémarré après l'épuisement suit la branche « dépense épuisée » (même résultat : consignation puis destruction).
2. **`instance_seule`** (session v8) : un objet d'erreur sans `id` (`{"success": false, …}`), un texte d'erreur 500, une réponse vide (`[]`, `{}`, `null`) ne sont plus « introuvable ». Absence établie seulement par : une liste NON vide ou un objet portant un autre identifiant, un statut exactement 404 accompagné d'un message exact (« not found », « no such instance », « does not exist »), ou un texte de ce sens exact ; « 404 » n'est plus cherché comme sous-chaîne. **Le texte réel de Vast pour une instance détruite n'est pas connu** : l'ordre E3 v6 demande de le recopier au compte rendu. Conséquence : trois réponses non concluantes de suite donnent `ARRET inventaire`, jamais `ARRET mort`.
3. **Masquage** : toute la `PIPESTATUS` est lue (inventaire, instance seule, journal) ; un échec de `masquer` donne « ALERTE masquage en échec … : relevé écarté », sans copie vidée ni fichier brut ; `instances.json` et `instances-apres.json` de `creation` et `apres-creation` sont masqués avant d'être écrits (fonction `vast_masque`, code 121 si le masquage échoue → pas de création). `set -u` : jeton GitHub absent → code 2 (la v8 sortait en code 1 par « unbound variable ») ; `NaN`, `inf` refusés par la garde CUDA.
4. **E2-2, stockage compté deux fois** : avec `--storage`, `dph_total` contient déjà `storage_total_cost`. `prix_carte = dph_total − storage_total_cost` ; somme lue par les gardes = `dph_total` (0,3617 contre 0,362 facturé ; la v8 comptait 0,4034). Tri des offres sur `dph_total`.
5. **E2-3** : la poussée initiale ne crée aucun commit : une branche de run complet porte `init` + trois commits (essai).
6. **E2-6, journal sur la branche** (amorce v7) : la consignation lancée par la ligne de commande (minuterie : échéance, dépense épuisée ; redémarrages) dépose `traces/consignation-…/journal-consignation.txt` (motif, heure, dernière ligne avant la consignation, 400 dernières lignes) et `t06-minuterie-fin.txt` (200 dernières lignes de la minuterie, avec « ÉCHÉANCE … atteinte (C14) ») et un commit « journal de l'instance (<motif>) ». La fin de run normale n'en crée pas. Une échéance pendant la poussée finale donne donc **5 commits** (essai).
7. **R-1694, R-1695, clause de mémoire de carte** : `gpu_ram>=N` ajouté au filtre, **N en Go** = partie entière de `memoire_carte_min_mo / 1024` (80 000 Mo → 78 ; 140 000 Mo → 136 ; 20 000 → 19), écrite et éprouvée : 40 960 Mo refusé, 81 920 Mo accepté ; le test montre aussi qu'en Mo (79 000) la clause ne rend rien. La garde locale reste en Mo. **Écart avec le message de la mère** : pour la relance elle parle de « 140 Go » ; la clause vaut 136 (140 000 // 1024), plus indulgente, et une H200 NVL (143 771 Mo = 140,4 Gio) passe.
8. **R-1696, R-1697, plafond d'épreuve** : plus de liste fermée 1,5 ou 3,5. `controles-epreuve` lit `plafond_usd` de la configuration et exige `T06_DEPENSE_EPREUVES_ANTERIEURES_USD` (dépense réelle et finale des autres épreuves du GO) : `plafond + dépense ≤ 4,9` (GO de 5 USD, marge 0,10, décimaux exacts : 0,6 + 4,3 passe, 4,31 non). La valeur est écrite dans `lancement.txt` et `creation` refait le contrôle. Configuration d'épreuve **E3 v3** (`config-t06-epreuve-e3-v3.json`, seule différence avec la v2 : `plafond_usd = 4.3`) ; configuration **E2 v3** (seule différence avec la v2 : `plafond_usd = 0.1`, pour le rejeu d'E2-6). **Aucun `.sha256` écrit** (la mère scelle).
9. **R-1700, relance** : `creation auto relance 0` marche dès la première création (essai) ; `filtre` et `choisir` de la carte « relance » éprouvés sur les valeurs réelles de 17:35Z (rang 1 à 3,3617 USD/h, stockage 0,041667, fiabilité 0,9906, CUDA 13,2, 64 cœurs, 193 278 Mo) ; un stockage de 0,097222 est refusé ; la clause vaut 136 Go.
