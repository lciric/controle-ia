### 1.2 Réponse à chaque question

- **Q1** — Base de confiance en trois lieux : hôte vérificateur (noyau, `sha256sum`, extracteur déterministe, analyseur de `RESULTAT:`, horloge), canal de sortie (sérialiseur, pare-feu), hôte d'exécution (isolation, amorce vérifiant l'empreinte d'entrée) (A l. 10-13) ; exclus : l'espace utilisateur du bac, les outils de hachage internes, le noyau invité d'une microVM (A l. 15-17). `bwrap` garde le noyau partagé entier dans la base, d'autant que (R-a) ouvre les espaces de noms ; gVisor réduit la surface ; Firecracker/Kata changent la classe par la frontière matérielle, au prix de la virtualisation imbriquée (A l. 20-22). Confiance 0,85 que déporter le vérificateur en session suffit à briser la circularité même sous `bwrap` ; 0,50 sur `/dev/kvm` en CPX32 (A l. 29). Option manquante : WebAssembly (WASI) sans système invité (A l. 31).
- **Q2** — Deux régimes : la boucle intra-fiche (sorties entre délimiteurs, temps, motifs de refus) est large ; la boucle inter-générations (comptes, étiquettes) est étroite, ≈ 2 bits par test, si aucun horodatage fin ni taille d'archive n'entre au matériau (A l. 50-56). Confiance 0,90 (A l. 62). Garde : gabarit strict des retours (code de retour, présence de `RESULTAT:`) ou arrêt sur sonde d'intégrité (A l. 63) ; option : exécution en un seul tour sans rétroaction (A l. 64) ; pièce : le formatage des retours dans `tests_de_mort_v2.py` (A l. 65).
- **Q3** — Archives déterministes et témoin prouvent l'identité entrée-sortie **sous l'hypothèse d'un noyau hôte intègre** ; `apt-get` au démarrage n'est pas reproductible, `etat-v1.txt` est le seul contrôle a posteriori (A l. 83-85). Journal d'appels système collecté hors du bac par le noyau hôte, avec deux limites : condition de course vérification/usage dans l'interposition (classe nommée, pas de recette) et calculs en mémoire invisibles ; seule la réexécution les couvre (A l. 87-89). L'attestation matérielle répond à une menace disjointe (opérateur du nuage) ; aucune offre confidentielle dans les relevés ; aucun secret sur la machine (A l. 91-94). Options 3a liaison logicielle actuelle, 3b plus journal `auditd`/eBPF et mesure d'intégrité IMA, 3c fournisseur confidentiel ; confiance 0,80 sur 3b (A l. 97-101). Garde : empreinte du script calculée avant son montage en lecture seule ; journalisation après la fin du groupe de processus (A l. 102, 107).
- **Q4** — Antériorités : Thompson, double compilation diverse de Wheeler, N versions, Knight et Leveson, N variantes (A l. 123-127). Gain élevé contre les artefacts d'implémentation ; **nul contre le contournement sémantique de la métrique** (A l. 130-131). Coût : série P doublée (0,24 → 0,48 ; 3,19 → 6,38) plus les faux désaccords si l'accord porte sur l'égalité exacte plutôt que sur le seuil (A l. 132). Options 4a aucune, 4b systématique, 4c **sélective** sur les seules « survit » ; confiance 0,80 sur 4c (A l. 136-139). Garde : même arbre Python en lecture seule, seule l'isolation varie (A l. 140) ; option : variantes décalées (A l. 141).
- **Q5** — Un script honnête n'a besoin que de la bibliothèque standard, de son dossier de travail et des fichiers de `index.json` ; canaris hors de ces chemins → fausses alertes théoriquement nulles sauf parcours générique ; seuil gelé à 1 accès (A l. 163-166). ## 2. Réponse propre de conv-audit (C), notée à part, non jugée

Circularité d'abord **logique** : le chiffre qui décide est déclaré par le script, le recalcul du noyau porte sur une statistique que le script choisit (C l. 37-40, 135-138) ; vérificateur **lié au préenregistrement**, calculé dans la session pour 0 USD, ou code de test écrit avant l'exécution par un traducteur séparé et joué sur une machine jetable **neuve** après destruction de celle de production (C l. 41-45, 110-115) ; base de confiance en deux colonnes, verdict contre confinement (C l. 59-82) ; attestation par réexécution et journal à scellement progressif, pas de matériel (C l. 146-164) ; redondance : la diversité qui compte est celle de l'auteur du calcul, gVisor sur la machine de vérification en génération 2, divergence honnête à mesurer sur 100 scripts (C l. 188-228) ; canaris = borne inférieure du sondage maladroit, informatifs en course 2, jeton de 128 bits, fiches impossibles plantées, pente par génération (C l. 232-263) ; suites publiques avec règle de lecture gelée en sept points (C l. 429-451) ; essai témoin n° 1 préenregistré (C l. 453-494) ; ordre en sept étapes, plafond ≈ 12 USD (C l. 496-523). C note que les « 25 environnements » sont p. 79 et non p. 76 (C l. 30-33), ce que la pièce 4 confirme (F l. 1116).

## 3. Pistes générales consensuelles

Un seul avis d'espèce est disponible : les accords ci-dessous sont entre Argon et la réponse propre de conv-audit, notée à part ; ils ne valent pas consensus entre espèces.

1. **Le vérificateur ne tourne pas sur l'hôte où le code de l'agent a tourné** (A l. 29-30, 247 ; C l. 112-115).
2. **Une machine virtuelle légère change la classe du confinement, pas celle de la circularité ; un vérificateur dans la microVM serait aussi circulaire** (A l. 22, 29 ; C l. 83-89).
3. **Le canal intra-fiche est la fuite riche ; le canal inter-générations est étroit ; garde commune : statut générique servi à l'expérimentateur** (A l. 55-56, 62-63 ; C l. 123, 139-140, 505).
4. **Constructions reproductibles et journaux ne prouvent rien au-delà de l'intégrité du noyau invité ; l'attestation matérielle vise une menace inverse et peut attendre** (A l. 85, 89, 92-94 ; C l. 146-147, 155-164).
5. **Journal d'appels système collecté hors du bac par le noyau hôte (`auditd`, eBPF), ciblé sur l'identité 64097** (A l. 88, 99 ; C l. 379-383).
6. **La redondance diverse ne protège pas contre un chiffre faux rendu fidèlement par les deux bacs** ; antériorités communes (Thompson, Wheeler, N versions, Knight et Leveson) ; faux désaccords par non-déterminisme, accord sur le seuil ou avec tolérance (A l. 123-132, 145 ; C l. 196-210, 227-228, 399-400).
7. **Les canaris sont une liste noire avec angle mort ; une mesure complémentaire est nécessaire** : liste blanche chez A (l. 169-170), désaccord déclaré/recalcul, jeton et pente chez C (l. 246-261) ; placement hors des chemins de données, sans comportement révélateur (A l. 182 ; C l. 238).
8. **Fausses alertes à étalonner sur un témoin honnête en S1 avant tout seuil éliminatoire** (A l. 177, 183 ; C l. 235, 262-263).
9. **Suites publiques communes** : LTP (`containers`, `seccomp`), kselftest `seccomp`, suite de bubblewrap, `test/syscalls` de gVisor, tests de Firecracker, runtime-tools, lynis (A l. 199-209 ; C l. 433-439) ; **lecture commune** : une suite éprouve les mécanismes, jamais notre politique ; un succès n'est pas une garantie ; un échec arrête (A l. 212-216 ; C l. 272-276, 442-451).
