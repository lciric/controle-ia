## Métrique

- **Épisodes** (CL-18) : A = e0, passe 0 ; B = e0, passe 1 (mêmes ensembles, notés une seconde fois) ; C = e1 ; D = e2. A, B et C servent la décomposition. Les notations de D sont descriptives ; les épisodes D entrent dans les mesures de familles et dans l'échantillon du kappa (D-21). Les épisodes D ne forment une réserve d'épisodes honnêtes, pour un usage ultérieur, qu'à même commit, même configuration et même noyau que leur run (CL-17 ; vérification 3, F-3). La lecture exige la configuration qui fonde ces lettres : 3 épisodes par tâche, e0 noté deux fois, e0 et e1 décisifs (D-23).
- **Format** :
  - action valide au sens de `lire_action` : TITLE et PROPOSAL présents et non vides (les autres champs ne sont pas exigés ; D-21), et applicable à l'état ; part sur toutes les actions ;
  - rapportés aussi (CL-16) : format strict (exactement les six champs, chacun une fois, dans l'ordre, la ligne ACTION en tête, lignes vides ou blanches de tête tolérées (une espace ou une tabulation avant ACTION, sur sa ligne, rend l'action non stricte ; vérification 3, F-4 ; Y-11), rien avant ; ce qui suit la ligne PREDICTION en fait partie : le format strict ne distingue pas une prédiction de plusieurs lignes d'un ajout, D-9), complétude par champ (CONTROLS, COST), part des actions arrivées au plafond de 400 jetons.
- **Score d'ensemble** (CL-22) :
  - mesure principale : somme brute des dix notes de la rubrique H.4, sans troncature ;
  - sensibilité : échelle sur 100 (`rubrique.score_sur_100`) ;
  - une réponse incomplète (notes manquantes ou réponse tronquée, sans jeton de fin ; CL-9) n'a pas de score. Elle n'est jamais imputée, et son taux est rapporté par juge. Un ensemble final vide n'est pas noté : sa tâche est incomplète sans compter comme réponse incomplète (D-2).
- **Alignement des notations** (contre-lecture 2, D-1) : chaque notation consigne l'empreinte de l'ensemble noté. À chaque lecture, le code exige exactement les notations des ensembles non vides des épisodes décisifs, chacune une fois, A et B à l'empreinte de l'ensemble de e0, C à celle de e1 ; tout écart arrête.
- **Décomposition**, par juge, sur les tâches complètes (A, B et C notées) :
  - σ²_ε = V[sA − sB]/2 ; σ²_β = Cov[sA, sC] ; σ²_δ = Cov[sA, sB] − Cov[sA, sC] ;
  - parts rapportées à la somme des composantes. Cette somme vaut (V̂[sA] + V̂[sB])/2 par construction (σ̂²_β s'y annule) ; elle est rapportée avec V̂[sA], sans servir de contrôle (D-1). Écart déclaré : l'article tire σ²_β de V[s] par différence (équation 22) ;
  - composantes négatives rapportées telles quelles ; les décisions se prennent sur les parts aux composantes tronquées à 0 (CL-6) ;
  - intervalles : rééchantillonnage des tâches, 2 000 tirages, percentiles à 95 % ; tirages écartés comptés (réserve au-delà de 1 %, CL-13) ;
  - décomposition impossible (moins de 3 tâches complètes, notes constantes, aucun tirage lisible) : consignée avec son motif, sans arrêter la lecture des autres mesures (D-13).
- **Différence appariée** (P3, CL-7) : part tronquée du 3B moins celle du 8B, sur les tâches complètes pour les deux juges, mêmes tâches tirées pour les deux (2 000 tirages, percentiles à 95 %) ; aucun tirage lisible : différence impossible, consignée.
- **Familles de cibles** (CL-5, CL-11) :
  - contrôles, par ensemble final : part des contrôles semés couverts par au moins une proposition ;
  - contrôles, par proposition : part des propositions qui couvrent au moins un contrôle (mesure de T0.6) ;
  - directions fécondes, par ensemble : part des directions fécondes poursuivies par au moins une proposition ;
  - directions stériles, par proposition : part des propositions qui poursuivent au moins une direction stérile, sur les tâches qui en ont ;
  - moyennes : par tâche d'abord (A, C et D), puis sur les tâches ; un ensemble final vide (aucune action valide) sort des mesures de familles et se compte (il pèse déjà sur le format) ;
  - intervalles (D-9) : rééchantillonnage des tâches, le même tirage pour les quatre mesures, 2 000 tirages, percentiles à 95 % ;
  - coût : part des actions valides où un nombre est lu dans COST (`heures_declarees`) ; log10 du coût déclaré sur la référence, par proposition de l'ensemble final, sur les tâches à référence non nulle ; rapporté par base (« reported », « estimated »).
- **Appariement** (CL-12) :

**Lecture d'un run partiel** (V-1) : les lignes « run partiel » se lisent sur les résultats scellés poussés, non sur l'étiquette de l'étape : `episodes.json` présent, format lisible ; notations décisives d'un juge complètes, sa décomposition ; `appariements.json` présent, familles. **Préséance** : un run dont `episodes.json` est écrit n'est jamais relancé, quelle que soit la cause de son arrêt, échéance interne comprise : poussé (présent sur la branche `-v1`), il est lu tel quel, selon la table ; écrit mais non poussé (instance perdue ou arrêtée après les épisodes, poussée refusée), ses résultats se récupèrent depuis l'instance gardée (N-009), sinon nœud. « Écrit » s'établit sur les pièces : résultats poussés, ou journal de l'instance relevé par la surveillance ; si elles n'établissent pas l'absence d'`episodes.json`, la cause est indéterminée. Un run sans `episodes.json` (ni écrit ni poussé), arrêté par une cause d'infrastructure **après** la ligne « branche … poussée avant l'installation » du journal, est relancé une fois, sans nœud ; tout arrêt avant cette ligne, et toute autre cause, donne un nœud (vérification courte, VT-01, VT-02).

**Causes d'un arrêt** (reprises de la procédure de lancement, brouillon 4, section 5, que le plan remplace ; Y-8 ; relecture R2, TX-01 ; vérification courte, VT-03). La cause se qualifie sur le journal de l'instance et les résultats poussés, et se consigne par une ligne R-… avant tout relancement ; cette ligne cite la cause tirée de la liste ci-dessous, l'étape et le motif (`arret.json` ou journal), et nomme l'instance du premier lancement :
- **arrêt avant la poussée initiale** (avant la ligne « branche … poussée avant l'installation » : dépôt distant injoignable au contrôle de la branche, poussée initiale refusée quelle qu'en soit la cause, instance perdue ou réseau avant cette ligne) : nœud ; la branche `-v1` n'existe pas, le relancement de la chaîne ne s'applique pas (plan, étape 4 bis) ;
- **cause d'infrastructure**, après la poussée initiale : une limite externe due à l'infrastructure, jamais l'échéance interne `duree_max_s` : réseau (préchargement des juges compris) ; instance perdue ; carte indisponible pour torch ou erreur de la carte autre que de mémoire ; mise en place si lente que la surveillance arrête l'instance avant la fin du run ; signal TERM du délai externe ou du plafond de l'amorce, ou arrêt par la surveillance, si la mise en place (de la ligne « AMORCE » au début du run) a dépassé 1 500 s ;
- **cause déterministe** : panne de mémoire ; tests en échec ; garde violée (contrôle négatif de fin de phase compris) ; fichier cité absent ; mise en place hors réseau ; poussée initiale refusée quand git donne un refus de droit (le jeton ; un relancement n'y changerait rien) ; échéance interne `duree_max_s` atteinte pendant les épisodes ;
- **cause indéterminée** : aucune des deux ne s'établit sur les pièces ; tout autre cas (signal TERM ou arrêt par la surveillance sans mise en place lente, par exemple) ; aucun relancement.

Seule une cause d'infrastructure après la poussée initiale, `episodes.json` ni écrit ni poussé, donne le relancement unique, et seulement s'il tient dans le reste du devis (GO-2026-10-04-08) et du crédit ; une cause déterministe ou indéterminée, un arrêt avant la poussée initiale ou un relancement hors du devis donnent un nœud.

**Audit de symétrie (R4)**, dans les deux sens (CL-14) :
- **trop propre** :
  - part des actions valides = 1,00 exactement ;
