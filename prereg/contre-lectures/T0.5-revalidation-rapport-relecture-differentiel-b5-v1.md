## Remarques

### Z-1 (mineure) — Contrôle des sceaux : la ligne versée au journal peut nommer un fichier conforme au lieu de la cause

- **Lieu** : script l. 130-133 (`… verifier "$CONFIG" "${CITES[@]}" >"$TRAVAIL/sceaux.txt" 2>&1`, puis `tail -n 1`) ; `src/controle_ia/scellement.py` l. 124-127 (« OK … » sur la sortie standard) et l. 138-143 (« ARRÊT : … » sur la sortie d'erreur) ; tests du script l. 131 et 154-155.
- **Problème.**
  - Redirigée vers un fichier, la sortie standard de Python est tamponnée par blocs ; la sortie d'erreur ne l'est que par lignes. La ligne « ARRÊT : … » est donc écrite d'abord, et les lignes « OK … » des fichiers déjà contrôlés ne le sont qu'à la sortie du processus, après elle. `tail -n 1` lit alors la dernière ligne « OK ».
  - Il faut pour cela que `PYTHONUNBUFFERED` ne soit pas posée. C'est le cas sur l'instance : l'image `python:3.11-bookworm` ne la pose pas, et la commande de création ne passe que `COMMIT`, `HF_TOKEN`, `GH_TOKEN` (et `BRANCHE` au relancement ; procédure l. 109-110). C'est aussi le cas dans les tests du script (`ENV_DE_BASE`). En revanche, la session exporte `PYTHONUNBUFFERED=1`, ce qui masque le défaut hors de ces tests.
  - Exemple : avec des tâches d'évaluation altérées, le journal dit « sceau non conforme parmi les fichiers cités (OK 7c2befed7819…  donnees/…/taches-entrainement.json) : arrêt avant l'installation ». Il nomme un fichier conforme, et la cause est perdue.
  - Cela vaut dès que le fichier fautif n'est pas le premier contrôlé (la configuration). L'arrêt, lui, est juste : code 2, avant l'installation.
  - Le test « empreinte altérée » (tâches d'évaluation, troisième fichier) produit exactement ce journal, et il passe : il ne cherche que « sceau non conforme ».
  - Accessoire : si `python3` manquait, le journal dirait « sceau non conforme » (la cause « command not found » suit entre parenthèses). Sans effet sur l'image citée, qui a `python3`.
- **Preuve.**
  - `scripts/essai_ordre_sortie_sceaux.sh` → `sorties/essai_ordre_sortie_sceaux.txt` :
    - cas 1, configuration altérée : la dernière ligne est la cause ;
    - cas 2, troisième fichier altéré : la dernière ligne est « OK ec0ec6b035fe…  donnees/r/taches-entrainement.json » ;
    - cas 3, même cas avec `PYTHONUNBUFFERED=1` (témoin) : la dernière ligne est la cause.
  - `scripts/essai_script_journal.py` → `sorties/essai_script_journal.txt`. Le script lui-même est lancé avec l'environnement minimal des tests, et seul `journal.txt` est lu : S2 donne la ligne fausse, S3 la bonne.
- **Correction proposée.**
  - Dans le script, l. 130 : `python3 -u` (ou `PYTHONUNBUFFERED=1` dans le préfixe), ou bien `grep -v '^OK ' "$TRAVAIL/sceaux.txt" | tail -n 1`.
  - Dans le test « empreinte altérée », vérifier que le journal nomme `taches-evaluation.json` et contient « ≠ scellée ».

## B. Script de l'instance

- **Contrôle des sceaux sans installation.**
  - `python3 -m controle_ia.scellement verifier` tourne sous Python 3.11.15 (même version mineure que l'image `python:3.11-bookworm`), sans `site-packages` (`-S`). Il importe `controle_ia` (fichier vide), `scellement` (`hashlib`, `re`, `sys`, `pathlib`) et `gardes` (`subprocess`, `pathlib` ; numpy seulement dans `exiger_numpy_minimal`, jamais appelée ici).
  - La racine du dépôt (premier élément du chemin d'import, avec `-m`) ne contient aucun fichier `.py` qui masquerait la bibliothèque standard. Les sceaux de l'extraction viennent de `sceller` (`extraire_t05.py`, l. 251 et 256), au format attendu : le cas sain passe.
- **Arrêts.** Sous `set -euo pipefail`, chaque échec ajouté ou déplacé arrête en code 2, consigné au journal, avant l'installation et avant le piège de sortie (rien n'est poussé, comme le dit B5 l. 142) :
  - branche présente (S5) ;
  - vérification de branche impossible (S4) ;
  - chemin, configuration, tâches ou sceau absents (tests) ;
  - sceau non conforme (tests ; S2, S3) ;
  - `python3` absent (S6).
  
  L'ordre suit la liste de B5 l. 142. Le cas sain passe (S1 et tests). Le seul défaut est le contenu du message des sceaux (Z-1).
- **Contrôle de branche.** Messages au journal, cause de git comprise pour le dépôt distant HTTPS (S4) ; rien n'est perdu pour l'adresse citée (Z-4 pour les autres formes). Les fichiers `ls-remote.err` et `sceaux.txt` sont écrits dans `$TRAVAIL`, hors du clone : l'arbre reste propre.
- **Environnement minimal des tests.** Il ne prive le script de rien d'utile :
  - `HOME` est posé par `_lancer` ; `PATH`, la langue et `TMPDIR` passent ;
  - les identités de git sont posées dans le clone ;
  - `mktemp` prend un gabarit explicite ;
  - `python3` est trouvé par `PATH` (avant l'activation du faux environnement) ;
  - les essais passent en langue « C » (la session n'a pas `LANG`) comme en UTF-8.
  
  Effet utile : les tests ne reçoivent plus `PYTHONUNBUFFERED`, comme l'instance. C'est d'ailleurs ce qui fait apparaître Z-1 dans le test, sans qu'il le vérifie.

## C. Lanceurs

- **Garde des mesures en mode réel.** Elle est juste, et placée après `episodes-<bras>` et `mesures-<bras>`, à l'étape « bras … ». Effets :
  - un arrêt laisse ces deux fichiers scellés et un `arret.json` sans bras lu, ce que décrivent B5 l. 95 et 146 ;
  - en mode jouet, elle ne fait rien ;
  - aucune variable ne reste indéfinie, aucun bras n'est sauté.
- **Carte par mot entier.** Juste : les noms renvoyés par la bibliothèque (« NVIDIA A100-SXM4-80GB », « NVIDIA A100 80GB PCIe ») passent ; « RTX A1000 » et « H100 » arrêtent. Effet de bord négligeable : « A100X » arrêterait aussi, ce qui est hors du domaine déclaré (SXM4 ou PCIe).
- **Lanceur du pilote.** La garde `0 < duree <= 15 000` refuse aussi les booléens, une valeur infinie ou non numérique (`nan` échoue à la comparaison). Elle est éprouvée sur 15 001, 16 200, 0, `True` et « À REMPLIR », et sur la borne 15 000 (cas sain ; Z-6 (d)).
