## Remarques

### V-1 (mineure) — Relancement : préséance non écrite face à la table, « lisible » non défini, et étiquette « épisodes » qui reste pendant le chargement des juges

**Où.**
- P3 l. 145 : « cause d'infrastructure : … réseau ; instance perdue ; … Un seul relancement » ;
- P3 l. 146 : « run partiel lisible … aucun relancement » ;
- B6 l. 182 : « run partiel : arrêt pendant les épisodes | aucune lecture ; nœud » ;
- B6 l. 183 : « run relancé … Un run partiel lisible selon les lignes ci-dessus … n'est pas relancé » ;
- lanceur l. 304 (l'étape devient « épisodes »), l. 329 (épisodes écrits), l. 340-342 (chargement du juge 3B, réseau en mode réel), l. 348 (l'étape suivante n'est posée qu'ici).

**Problème.**
- Le texte ne dit pas laquelle des deux règles l'emporte quand une cause d'infrastructure laisse un run partiel poussé :
  - « cause d'infrastructure → un relancement, sans nœud » ;
  - ou la table : « arrêt pendant les épisodes → nœud » ; « lisible → pas de relancement ».
- Il ne dit pas non plus ce qu'est un run « lisible ». Une seule ligne de la table dit « tout est lisible ». Les autres lisent une partie : appariement, décisives (avec un juge complet ou non).
- Le cas n'est pas théorique. Une panne de réseau au téléchargement du juge 3B, juste après l'écriture des 192 épisodes, laisse :
  - `episodes.json` écrit et scellé ;
  - un `arret.json` qui dit « épisodes ».
- Trois lectures sont alors possibles :
  - « aucune lecture ; nœud », par l'étiquette ;
  - « format lisible, run lu tel quel », par les fichiers ;
  - « réseau → relancement à l'identique », soit environ 4 heures de carte payées sans décision.
- Un arrêt pendant le chargement de l'agent (étape « chargement ») n'a, lui, aucune ligne dans la table.

**Preuve.** `scripts/test_essai_chargement_juge.py` → `sorties/essai_chargement_juge.txt` : code du dépôt, mode jouet, dépôt jetable, téléchargement du juge 3B qui échoue (réseau simulé). Fichiers écrits : `episodes.json` et `arret.json`. Étape consignée : « épisodes ». Épisodes écrits : 4 sur 4.

**Correction proposée** (texte : B6, table de lecture ; P3, section 5) :
- définir « lisible » par les résultats scellés, et non par l'étiquette de l'étape :
  - `episodes.json` présent : format lisible ;
  - notations décisives complètes : décomposition ;
  - `appariements.json` présent : familles ;
- écrire la préséance :
  - un run lisible n'est jamais relancé, quelle qu'en soit la cause ;
  - un run non lisible (rien de poussé, ou arrêt avant la fin des épisodes) dont la cause est d'infrastructure est relancé une fois, sans nœud ;
  - sinon, nœud ;
- ajouter une ligne « arrêt au chargement (avant le premier épisode) », ou l'inclure dans la ligne des épisodes.

Facultatif (code gelé, avant le commit cité) : poser `etat["etape"] = "chargement des juges"` avant le lanceur l. 338, pour que l'étiquette dise vrai.
