### W-9 — Contrôle de la branche : repli silencieux si le dépôt distant ne répond pas (mineure)

- **Lieu** : script, l. 74-77.
- **Problème.**
  - `git ls-remote --exit-code` rend 2 si la branche manque et 128 si le dépôt distant est injoignable. Le script lit tout code non nul comme « branche absente » : la garde est alors sautée en silence (R5).
  - Une branche déjà présente ne serait vue qu'à la poussée finale, qui serait refusée : les résultats resteraient sur l'instance.
  - Le motif est aussi comparé par la fin du nom : « t05-revalidation-v1 » trouve « calcul/t05-revalidation-v1 ». Cela ne produit qu'un arrêt de trop, sans gravité.
- **Preuve** : `sorties/w_essais_script.txt`. Avec un dépôt distant injoignable (code 128), la garde laisse passer.
- **Correction proposée** : utiliser `git ls-remote --exit-code origin "refs/heads/$BRANCHE"`. Code 0 → arrêt ; code 2 → suite ; tout autre code → arrêt « vérification impossible ».

## C. Fautes nouvelles dans le code et les scripts de l'instance

- **Une instance saine arrêtée à tort ?**
  - Oui, de façon sûre, si les fichiers de tâches ne sont pas dans l'arbre du commit (W-1). L'arrêt survient après l'installation et les tests.

    - après une répétition ou un premier arrêt qui a poussé la branche par défaut, l'arrêt est sans coût de calcul (W-11) ;
    - si l'image colore la sortie de pytest (W-10) ;
    - le préenregistrement absent n'arrête qu'après l'installation (W-10), ce qui est juste mais tardif.

- **Une instance défaillante qui passe ?**
  - Le dépôt distant injoignable laisse passer le contrôle de branche (W-9).
  - Une carte autre qu'une A100, avec au moins 75 Gio, passe ; elle est seulement consignée (W-13).
  - Une carte invisible pour torch, par exemple un pilote CUDA trop ancien pour la roue CUDA 13, est bien arrêtée avant les tests.
- **Panne hors du jeu des épisodes** : elle arrête tout le run (W-2).
